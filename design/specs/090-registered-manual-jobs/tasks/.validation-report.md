## Findings

### Finding 1 (CONTRADICTION): Inconsistent `trigger_error` status text between CLI (T06) and design doc/frontend (T07)

- **Design doc** (`design.md`, Operator Surfaces section, line 299): `Completed with `trigger_error`: "Schedule stopped after trigger error."`
- **T07** (`job-detail.tsx` prompt): `completed + trigger_error: "Schedule stopped after trigger error."` — matches the design doc exactly.
- **T06** (`cli/commands/job.py` prompt): `completed with trigger_error: "Schedule stopped (trigger error)"` — **different wording** from both the design doc and T07.

All other status strings (Timing unavailable, Legacy status unknown, Waiting for entity time, Schedule completed, Manual only) match verbatim (modulo trailing period) between T06, T07, and the design doc. Only this one string diverges. If implemented as written, the CLI and web UI will show different text for the same status/reason combination, and neither will match the exact string the design doc specifies for CLI rendering (it only gives one canonical string, presumably intended for both surfaces). Fix: change T06's text to `"Schedule stopped after trigger error."` to match the design doc and T07.

### Finding 2 (COVERAGE GAP, task-dependency): T08 missing `depends_on: T07`; AC#10 Verify checklist narrower than AC#10 text

- **Design doc** AC#10: "Existing scheduler unit, integration, and system suites pass after public type/removal API migrations, and `prek -a` passes." AC#10 is attributed solely to T08's frontmatter (`implements: ["AC#10"]`), but T08's Verify checklist only checks `prek -a` and a grep for leftover old symbol names — it does not restate or re-verify "existing scheduler unit, integration, and system suites pass." That specific instruction is written into T05's Prompt ("Full test suite pass: After this task, all existing scheduler unit, integration, and system tests must pass...") but T05's frontmatter does not list AC#10, and T05's own Verify checklist doesn't check it either. The AC#10 checkbox is nominally "owned" by T08 but the substance of what it requires is done, unverified-in-checklist, in T05.
- Separately: T08 depends only on `["T06"]`, but T08's own instructions include "Regenerate doc screenshots if handlers/job views visibly changed" (`web_ui_handlers`, `web_ui_jobs`). Those screenshots capture the frontend UI, which is built in T07 (schedule-status badges, Run Now toast feedback). T07 also depends only on T06, making T07 and T08 sibling tasks with no ordering guarantee between them. If an orchestrator runs T08 before T07, the regenerated screenshots will not reflect the new UI (no status badges, no toasts), silently shipping stale screenshots that don't match the shipped frontend.
- **Fix:** Add `T07` to T08's `depends_on`, and add an explicit AC#10 checklist item to T08 (or T05) that says "run `uv run nox -s tests` (or the equivalent scheduler-scoped suites) and confirm zero failures" rather than relying on `prek -a` alone (which does not run the test suite).
