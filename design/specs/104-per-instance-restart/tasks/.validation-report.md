## Coverage Gaps

### Gap 1 (minor): "all instances change" test not tied to a Verify item

Design doc's `## Test Strategy → New Test Coverage` explicitly lists:

> FR#1: Unit test — same length, all configs differ, verify each reloads individually.

This is distinct from AC#1 (which covers only a *single*-instance-changed scenario) and from the "Edge Cases" entry "All instances change" (design.md lines 75-76). Neither T04's Prompt "Tests" bullet list nor its Verify checklist names this scenario explicitly — T04's Verify items are AC#1, AC#2, AC#3, AC#8, AC#9 (plus the bare FR#1/2/3/7/8 restatements), none of which map to "all indices differ, each reloads individually." The `apply_changes()` implementation as specified would handle this case correctly as a natural consequence of the `changed_indices` loop (no special-casing needed), so this is a test-coverage gap, not an implementation gap — but it means an implementer following T04's Verify checklist literally could skip writing this specific test.

**Recommendation:** Add a line to T04's Verify section, e.g. `- [ ] FR#1 (all-changed case): Unit test — same instance-list length, every instance's config differs, verify each instance reloads individually (not via reload_app fallback).` Low severity — does not block execution, since the underlying code path is already required by AC#1's sibling-isolation assertion and by the `apply_changes()` pseudocode in the Architecture section.
