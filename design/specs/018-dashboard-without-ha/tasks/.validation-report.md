## Additional Findings (outside the strict FR/AC traceability check)

These do not change the PASS verdict (no FR/AC coverage gap, no direct design-vs-task contradiction) but are real defects worth fixing before execution:

1. **Documentation Updates requirement has no owning task.** Design.md's "Documentation Updates" section states: *"`CLAUDE.md` Architecture section — update the Resource Hierarchy description to note that StateProxy and ApiResource no longer depend on WebsocketService, and that WebsocketService marks ready unconditionally (lifecycle readiness ≠ HA connected)."* This is not tagged with an FR#N/AC#N, so it doesn't surface in the identifier-based traceability matrix, but it is a stated deliverable. No task (`T01`, `T02`, `T03`) targets `CLAUDE.md`, and a repo-wide grep for "CLAUDE.md" across the tasks directory returns nothing. Recommend adding a target-file line and a Verify item to T03 (or a small T04) to update CLAUDE.md's Resource Hierarchy paragraph.

2. **T03 Prompt cites a nonexistent file path.** The Prompt says: *"use `create_hassette_stub()` from `src/hassette/test_utils/web_helpers.py`"* — but `create_hassette_stub` is actually defined in `src/hassette/test_utils/web_mocks.py`. There is no `web_helpers.py` in this repo (confirmed via `find`); T03's own Target Files and Focus sections correctly cite `web_mocks.py`, so this is an internal inconsistency within T03 itself, not a design-doc contradiction. It's a plausible source of executor confusion (dead import path) and should be corrected to `web_mocks.py` before T03 runs.

3. **Minor: AC#1's literal wording vs. T03's Verify text.** Design.md's AC#1 says `uv run pytest tests/` passes; T03's Prompt and Verify use `ptest -n 4` instead. This matches the project's actual local test-execution convention (a cgroup-scoped pytest wrapper used to avoid the orphan-test reaper killing long runs) rather than diverging from intent, so it is not flagged as a contradiction — but worth noting as a literal-text mismatch if a future automated check ever tries to string-match AC#1 against the Verify line.

4. **Minor: design.md's "30s startup timeout" claim.** Both the Problem section and T01's Summary state WebsocketService's startup timeout is 30s. The actual `RestartSpec` for `WebsocketService` (`websocket_service.py:82-87`) explicitly sets `startup_timeout_seconds=60` (the generic default in `RestartSpec` is 30.0, but WS overrides it to 60). This doesn't affect any task's correctness or Verify criteria — no task checks the timeout value — but the design doc's stated number is inaccurate to the current code.
