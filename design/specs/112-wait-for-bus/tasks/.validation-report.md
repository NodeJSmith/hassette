## Warnings (non-blocking)

1. **context.md Key Decision #6 phrasing is imprecise.** It reads: "Only match new events — pre-existing state does not resolve the wait (`state_check_now=False` default)." This implies a `state_check_now` parameter exists with a default value. design.md's Non-Goals and Key Constraints sections are explicit that `state_check_now` is **not** being added at all ("Do not add a `state_check_now` parameter... future enhancement"). None of the task files (T01–T04) introduce such a parameter, so the actual implementation plan is correct — only context.md's summary wording is misleading. Recommend rewording to "Only new events match — there is no `state_check_now` parameter in this iteration" before execution, to avoid an implementer mistakenly adding the parameter based on context.md's phrasing alone.

2. **T02 has three tests without dedicated Verify items.** T02's "Tests to write" section lists four tests: (1) real Bus event dispatch resolves wait_for, (2) arm-before-fire composition with call_service [AC#6], (3) WhereClause filtering with real dispatch, (4) concurrent waits with real dispatch. Only test 2 (AC#6) has a corresponding Verify checklist item — tests 1, 3, and 4 are described in the Prompt but not tracked by any `- [ ]` item. This does not create a coverage gap against design.md (FR#1/FR#9 are already fully covered by T01's unit-test Verify items, and the Test Strategy table's "Real Bus event dispatch resolves wait_for / Integration / FR#1" row is satisfied by T02's Prompt content even without its own Verify line), but an executor grading T02 solely against its Verify checklist could consider the task complete without confirming tests 1/3/4 were actually written. Recommend adding lightweight Verify items for these three tests for completeness, though this is not required for the plan to PASS.
