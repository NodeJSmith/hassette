## Warnings

- **T04 Focus section has factually wrong fixture/helper names (verified against source).** T04 states: "The `conftest.py` provides `telemetry_service` and `db_path` fixtures. `helpers.py` provides `insert_execution(db_path, ...)`, `insert_listener(db_path, ...)`, `insert_job(db_path, ...)`." The actual `tests/integration/telemetry/conftest.py` fixture is named `query_service` (typed `TelemetryQueryService`), not `telemetry_service`; there is no `db_path` fixture. `helpers.py`'s `insert_listener`, `insert_job`, and `insert_execution` all take `db_svc: DatabaseService` as their first positional argument, not a path. (This directory even has its own `CLAUDE.md` confirming `query_service` and `db` as the available fixtures.) T04's Target Files does instruct reading `conftest.py`/`helpers.py` first, which would surface the correct names, but the Focus section's wrong guidance risks misleading an implementer who trusts it over the raw files, or causes rework. Recommend fixing T04's Focus text to reference `query_service` and `db_svc` before this task runs.

- **T13's `depends_on` is too narrow for its own Verify criterion.** T13 declares `depends_on: ["T01", "T02"]`, but its AC#9 Verify step requires the *entire* suite to pass: `prek -a`, `ptest -- tests/unit tests/integration -n 4`, and `cd frontend && npm run build && npm test`. T06–T09 have no declared dependencies and could be scheduled in parallel with T13 under the stated graph, and T03/T04/T05/T10/T11/T12 are not in T13's dependency chain at all. If task orchestration runs tasks as soon as their declared deps clear (rather than strictly in file order), T13 could execute before the frontend decomposition (T06-T10), the frontend test splits (T11, T12), or the backend UNION/test-reorg work (T03-T05) is done, and its full-suite verification would fail for reasons unrelated to T13's own doc changes. Recommend widening `depends_on` to include the terminal task of each track (e.g., `T05`, `T11`, `T12` — which transitively pull in T03/T04/T06-T10) so T13 genuinely runs last.

- **T07/T08/T09 all point to the wrong follow-up task.** Each of T07, T08, and T09 says "Do NOT modify `handler-detail-layout.tsx` yet — that happens in T11" (T07 additionally: "Note this for T11" regarding `job-detail.tsx`'s `.subtitle` import). Recommend a one-word fix (T11 → T10) in all three files.

Verified against `execution_queries.py`: `source_tier_clause` is used uniformly by all three, but `since_clause` (which only produces a single `>= :since` lower bound) is used by `get_app_recent_activity` and `get_per_app_last_errors` — `get_per_app_activity_buckets` instead needs a **dual bound** (`>= :since AND < :now`) plus a `bucket_idx` expression computed inline in its SELECT list, which isn't something `since_clause` produces. Recommend adding one sentence to T03 noting this method's divergent shape and the intended use of the escape-hatch parameters.
