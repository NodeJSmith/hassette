LINE 28: ### OpenAPI¶
LINE 29: FastAPI generates a "schema" with all your API using the OpenAPI standard for defining APIs.
LINE 30: #### "Schema"¶
LINE 31: A "schema" is a definition or description of something. Not the code that implements it, but just an abstract description.
LINE 32: #### API "schema"¶
LINE 33: In this case, [OpenAPI](https://github.com/OAI/OpenAPI-Specification) is a specification that dictates how to define a schema of your API.
LINE 34: This schema definition includes your API paths, the possible parameters they take, etc.
LINE 35: #### Data "schema"¶
LINE 36: The term "schema" might also refer to the shape of some data, like a JSON content.
LINE 37: In that case, it would mean the JSON attributes, and data types they have, etc.
LINE 38: #### OpenAPI and JSON Schema¶
LINE 39: OpenAPI defines an API schema for your API. And that schema includes definitions (or "schemas") of the data sent and received by your API using JSON Schema , the standard for JSON data schemas.
LINE 40: #### Check theopenapi.json¶
LINE 41: If you are curious about what the raw OpenAPI schema looks like, FastAPI automatically generates a JSON (schema) with the descriptions of all your API.
LINE 42: You can see it directly at: [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json) .
LINE 43: It will show a JSON starting with something like:
LINE 44: ```

...

LINE 47: #### What is OpenAPI for¶
LINE 48: The OpenAPI schema is what powers the two interactive documentation systems included.
LINE 49: And there are dozens of alternatives, all based on OpenAPI. You could easily add any of those alternatives to your application built with FastAPI .
LINE 50: You could also use it to generate code automatically, for clients that communicate with your API. For example, frontend, mobile or IoT applications.
LINE 51: ### Configure the appentrypointinpyproject.toml¶
LINE 52: You can configure where your app is located in a pyproject.toml file like:
LINE 53: ```
LINE 54: [tool.fastapi]
entrypoint = "main:app"
LINE 55: ```
LINE 56: If your code was structured like:
LINE 57: ```
LINE 58: .
├── backend
│   ├── main.py
│   ├── __init__.py
LINE 59: ```
LINE 60: Then you would set the entrypoint as:
LINE 61: ```
LINE 62: [tool.fastapi]
entrypoint = "backend.main:app"
LINE 63: ```
LINE 64: which would be equivalent to:
LINE 65: ```
LINE 66: from backend.main import app
LINE 67: ```
LINE 68: ### fastapi devwith path or with--entrypointCLI option¶
LINE 69: You can also pass the file path to the fastapi dev command, and it will guess the FastAPI app object to use:
LINE 70: ```
LINE 71: $ uv run fastapi dev main.py
LINE 72: ```
LINE 73: Or, you can also pass the --entrypoint option to the fastapi dev command:
LINE 74: ```
LINE 75: $ uv run fastapi dev --entrypoint main:app
LINE 76: ```
LINE 77: But you would have to remember to pass the correct path\entrypoint every time you call the fastapi command.
LINE 78: Additionally, other tools might not be able to find it, for example the [VS Code Extension](../../editor-support/) or [FastAPI Cloud](https://fastapicloud.com) , so it is recommended to use the entrypoint in pyproject.toml .

LINE 84: ## Recap, step by step¶
LINE 85: ### Step 1: importFastAPI¶
LINE 86: [TAB: Python 3.10+]
LINE 87: ```
LINE 88: from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}
LINE 89: ```
LINE 90: FastAPI is a Python class that provides all the functionality for your API.
LINE 91: [ADMONITION: Technical Details]
LINE 92:   FastAPI is a class that inherits directly from Starlette .
LINE 93:   You can use all the [Starlette](https://starlette.dev/) functionality with FastAPI too.
LINE 94: ### Step 2: create aFastAPI"instance"¶
LINE 95: [TAB: Python 3.10+]
LINE 96: ```
LINE 97: from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}
LINE 98: ```
LINE 99: Here the app variable will be an "instance" of the class FastAPI .
LINE 100: This will be the main point of interaction to create all your API.
LINE 101: ### Step 3: create apath operation¶
LINE 102: #### Path¶
LINE 103: "Path" here refers to the last part of the URL starting from the first / .
LINE 104: So, in a URL like:
LINE 105: ```
LINE 106: https://example.com/items/foo
LINE 107: ```
LINE 108: ...the path would be:
LINE 109: ```
LINE 110: /items/foo
LINE 111: ```
LINE 112: [ADMONITION: Note]
LINE 113:   A "path" is also commonly called an "endpoint" or a "route".
LINE 114: While building an API, the "path" is the main way to separate "concerns" and "resources".
LINE 115: #### Operation¶
LINE 116: "Operation" here refers to one of the HTTP "methods".
LINE 117: One of:
LINE 118: - POST
LINE 119: - GET
LINE 120: - PUT
LINE 121: - DELETE
LINE 122: ...and the more exotic ones:
LINE 123: - OPTIONS
LINE 124: - HEAD
LINE 125: - PATCH
LINE 126: - TRACE
LINE 127: In the HTTP protocol, you can communicate to each path using one (or more) of these "methods".
LINE 128: When building APIs, you normally use these specific HTTP methods to perform a specific action.
LINE 129: Normally you use:
LINE 130: - POST : to create data.
LINE 131: - GET : to read data.
LINE 132: - PUT : to update data.
LINE 133: - DELETE : to delete data.
LINE 134: So, in OpenAPI, each of the HTTP methods is called an "operation".
LINE 135: We are going to call them " operations " too.
LINE 136: #### Define apath operation decorator¶
LINE 137: [TAB: Python 3.10+]
LINE 138: ```
LINE 139: from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}
LINE 140: ```
LINE 141: The @app.get("/") tells FastAPI that the function right below is in charge of handling requests that go to:
LINE 142: - the path /
LINE 143: - using a get operation
LINE 144: [ADMONITION: @decoratorInfo]
LINE 145:   That @something syntax in Python is called a "decorator".
LINE 146:   You put it on top of a function. Like a pretty decorative hat (I guess that's where the term came from).
LINE 147:   A "decorator" takes the function below and does something with it.
LINE 148:   In our case, this decorator tells FastAPI that the function below corresponds to the path / with an operation get .
LINE 149:   It is the " path operation decorator ".
LINE 150: You can also use the other operations:
LINE 151: - @app.post()
LINE 152: - @app.put()
LINE 153: - @app.delete()
LINE 154: And the more exotic ones:
LINE 155: - @app.options()
LINE 156: - @app.head()
LINE 157: - @app.patch()
LINE 158: - @app.trace()
LINE 159: [ADMONITION: Tip]
LINE 160:   You are free to use each operation (HTTP method) as you wish.
LINE 161:   FastAPI doesn't enforce any specific meaning.
LINE 162:   The information here is presented as a guideline, not a requirement.
LINE 163:   For example, when using GraphQL you normally perform all the actions using only POST operations.
LINE 164: ### Step 4: define thepath operation function¶
LINE 165: This is our " path operation function ":
LINE 166: - path : is / .
LINE 167: - operation : is get .
LINE 168: - function : is the function below the "decorator" (below @app.get("/") ).
LINE 169: [TAB: Python 3.10+]
LINE 170: ```
LINE 171: from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}
LINE 172: ```
LINE 173: This is a Python function.
LINE 174: It will be called by FastAPI whenever it receives a request to the URL " / " using a GET operation.
LINE 175: In this case, it is an async function.
LINE 176: You could also define it as a normal function instead of async def :
LINE 177: [TAB: Python 3.10+]
LINE 178: ```
LINE 179: from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def root():
    return {"message": "Hello World"}
LINE 180: ```
LINE 181: ### Step 5: return the content¶
LINE 182: [TAB: Python 3.10+]
LINE 183: ```
LINE 184: from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello World"}
LINE 185: ```
LINE 186: You can return a dict , list , singular values as str , int , etc.
LINE 187: You can also return Pydantic models (you'll see more about that later).
LINE 188: There are many other objects and models that will be automatically converted to JSON (including ORMs, etc). Try using your favorite ones, it's highly probable that they are already supported.
